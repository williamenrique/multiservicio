SECCIÓN 1 — REQUISITOS DEL SISTEMA
================================================================================

1.1 Requisitos mínimos del servidor:
  - PHP 8.0 o superior
  - MySQL 5.7+ o MariaDB 10.3+
  - Apache 2.4+ con mod_rewrite habilitado (o Nginx con reglas equivalentes)
  - Extensión PHP: PDO, pdo_mysql, mbstring, gd, curl, json, fileinfo, openssl
  - Composer 2.x (gestor de dependencias PHP)
  - Node.js 18+ (solo para el servicio de WhatsApp, opcional)
  - Espacio en disco: ~50 MB (más uploads)

1.2 Extensiones PHP requeridas (verificar con phpinfo()):
  - pdo_mysql       → Conexión a base de datos
  - mbstring        → Manejo de UTF-8
  - gd              → Generación de imágenes (QR, fotos)
  - curl            → Comunicación con servidor Node.js (WhatsApp)
  - openssl         → Encriptación AES-256-CBC
  - fileinfo        → Validación de archivos subidos
  - json            → Manejo de datos JSON
  - dom             → DomPDF (generación de PDFs)

SECCIÓN 2 — INSTALACIÓN EN SERVIDOR LOCAL (XAMPP / WAMP / Laragon)
================================================================================

2.1 Clonar o copiar el proyecto
  ─────────────────────────────
  Copia la carpeta completa del proyecto a la raíz de tu servidor local:

    XAMPP:   C:\xampp\htdocs\multiservicio\
    WAMP:    C:\wamp64\www\multiservicio\
    Laragon: C:\laragon\www\multiservicio\

2.2 Configurar VirtualHost (XAMPP) — OPCIONAL pero recomendado
  ─────────────────────────────────────────────────────────────
  Edita el archivo:
    C:\xampp\apache\conf\extra\httpd-vhosts.conf

  Agrega al final:
    <VirtualHost *:80>
        DocumentRoot "C:/xampp/htdocs/multiservicio"
        ServerName multiservicio.test
        <Directory "C:/xampp/htdocs/multiservicio">
            Options Indexes FollowSymLinks
            AllowOverride All
            Require all granted
        </Directory>
    </VirtualHost>

  Edita el archivo de hosts del sistema:
    C:\Windows\System32\drivers\etc\hosts

  Agrega la línea:
    127.0.0.1   multiservicio.test

  Reinicia Apache desde el panel de control de XAMPP.

2.3 Instalar dependencias con Composer
──────────────────────────────────────
  Abre una terminal (PowerShell o CMD) en la raíz del proyecto:
    cd C:\xampp\htdocs\multiservicio

  Si NO tienes Composer instalado globalmente:
    - Descarga Composer desde https://getcomposer.org/
    - O usa el comando: php composer.phar install

  Si YA tienes Composer instalado:
    composer install

  Esto instalará en vendor/:
    - dompdf/dompdf          (^3.1)  → Generación de PDFs
    - phpmailer/phpmailer    (^6.8)  → Envío de correos SMTP
    - chillerlan/php-qrcode  (^6.0)  → Códigos QR

2.3 Crear la base de datos
──────────────────────────
  Opción A — Desde phpMyAdmin:
    1. Abre http://localhost/phpmyadmin
    2. Crea una nueva base de datos llamada: multiservicio_2.0
    3. Selecciona cotejamiento: utf8mb4_spanish_ci
    4. Ve a la pestaña "Importar"
    5. Selecciona el archivo: sql/database_schema_2.0.sql
    6. Haz clic en "Continuar"

  Opción B — Desde terminal:
    mysql -u root -p < sql/database_schema_2.0.sql

2.4 Configurar el archivo de constantes
───────────────────────────────────────
  Edita: app/Config/config.php

  Valores por defecto para desarrollo local:
    DB_HOST = 'localhost'
    DB_USER = 'root'
    DB_PASS = ''              ← Contraseña de MySQL (vacía en XAMPP por defecto)
    DB_NAME = 'multiservicio_2.0'

  La URL se detecta automáticamente. Si usas VirtualHost, se ajustará solo.
  Si accedes como http://localhost/multiservicio, también funciona.

  ⚠ ACLARACIÓN IMPORTANTE — ¿Dónde se configura el dominio?
  ─────────────────────────────────────────────────────────
  ¡NO necesitas cambiar nada manualmente! El sistema detecta el dominio
  de forma automática mediante la constante URLROOT definida en
  app/Config/config.php (líneas 26-36).

  CÓMO FUNCIONA LA DETECCIÓN AUTOMÁTICA DE URLROOT:
  ─────────────────────────────────────────────────
  El sistema usa este orden de prioridad:

    1. Si existe un archivo .env con URLROOT=... → USA ESE VALOR
       (recomendado para producción)

    2. Si NO hay .env → DETECTA AUTOMÁTICAMENTE:
       - Lee $_SERVER['HTTP_HOST'] (el dominio que el visitante usó)
       - Lee $_SERVER['HTTPS'] para saber si es http o https
       - Lee $_SERVER['SCRIPT_NAME'] para detectar subcarpetas

  EJEMPLOS DE DETECCIÓN AUTOMÁTICA:
  ─────────────────────────────────
  • Local XAMPP:   http://localhost/multiservicio  → URLROOT = http://localhost/multiservicio
  • Local VirtualHost: http://multiservicio.test     → URLROOT = http://multiservicio.test
  • Producción:    https://multiservicio.com         → URLROOT = https://multiservicio.com
  • Producción:    https://www.miservicio.net        → URLROOT = https://www.miservicio.net

  CUÁNDO USAR EL ARCHIVO .ENV PARA FORZAR LA URL:
  ────────────────────────────────────────────────
  Solo necesitas crear un .env con URLROOT si:
    - Usas un proxy inverso (Cloudflare, Nginx reverse proxy)
    - El dominio detectado automáticamente no es el correcto
    - Quieres forzar https aunque el servidor no lo detecte

  En el 95% de los casos, la detección automática funciona sin
  que tengas que tocar nada. Solo contratas tu dominio, apuntas
  el DNS al hosting, y el sistema lo lee solo.

SECCIÓN 4 — CONFIGURACIÓN DEL SERVIDOR NODE.JS PARA WHATSAPP
================================================================================

4.1 ¿Qué hace el servidor Node.js?
──────────────────────────────────
  El sistema PHP envía peticiones HTTP (cURL) a un servidor Node.js local
  que se comunica con la API de WhatsApp Web usando la librería baileys.
  Esto permite enviar notificaciones de pedidos por WhatsApp.

  Si el servidor Node.js NO está disponible, el sistema sigue funcionando
  normalmente y muestra un aviso tipo toast al usuario.

4.2 Requisitos del servidor WhatsApp
────────────────────────────────────
  - Node.js 18 o superior
  - npm (incluido con Node.js)
  - Un número de WhatsApp activo (se escanea un código QR para vincularlo)

4.3 Instalación del servidor WhatsApp
─────────────────────────────────────
  El código del servidor Node.js NO está incluido en este proyecto.
  Debes crearlo en una carpeta separada, por ejemplo:

    C:\whatsapp-server\   (local)
    /opt/whatsapp-server/ (producción)

  Estructura del servidor:
    whatsapp-server/
    ├── package.json
    ├── server.js
    └── auth_info/          ← Se crea automáticamente al vincular WhatsApp

  package.json:
    {
      "name": "whatsapp-server",
      "version": "1.0.0",
      "dependencies": {
        "@whiskeysockets/baileys": "^6.7.0",
        "express": "^4.18.0",
        "qrcode-terminal": "^0.12.0"
      }
    }

  Instalar dependencias:
    cd whatsapp-server
    npm install

4.4 Código del servidor (server.js)
───────────────────────────────────
  Crea un archivo server.js con el siguiente contenido:

    const express = require('express');
    const { makeWASocket, useMultiFileAuthState, DisconnectReason } = require('@whiskeysockets/baileys');
    const qrcode = require('qrcode-terminal');

    const app = express();
    app.use(express.json());

    let sock = null;

    async function connectWhatsApp() {
        const { state, saveCreds } = await useMultiFileAuthState('auth_info');

        sock = makeWASocket({
            auth: state,
            printQRInTerminal: true
        });

        sock.ev.on('creds.update', saveCreds);

        sock.ev.on('connection.update', (update) => {
            const { connection, lastDisconnect } = update;
            if (connection === 'close') {
                const shouldReconnect = lastDisconnect?.error?.output?.statusCode !== DisconnectReason.loggedOut;
                if (shouldReconnect) {
                    console.log('Reconectando...');
                    connectWhatsApp();
                } else {
                    console.log('Sesión cerrada. Borra auth_info/ y reinicia.');
                }
            } else if (connection === 'open') {
                console.log('✅ WhatsApp conectado');
            }
        });
    }

    // Endpoint que recibe las peticiones del PHP
    app.post('/enviar-pedido', async (req, res) => {
        const { telefono, mensaje } = req.body;

        if (!telefono || !mensaje) {
            return res.status(400).json({ success: false, error: 'Faltan datos' });
        }

        try {
            const jid = telefono + '@s.whatsapp.net';
            await sock.sendMessage(jid, { text: mensaje });
            res.json({ success: true, mensaje: 'Mensaje enviado' });
        } catch (err) {
            res.status(500).json({ success: false, error: err.message });
        }
    });

    app.listen(3000, () => {
        console.log('Servidor WhatsApp en puerto 3000');
        connectWhatsApp();
    });

4.5 Iniciar el servidor y vincular WhatsApp
───────────────────────────────────────────
  1. Ejecuta: node server.js
  2. Aparecerá un código QR en la terminal
  3. Abre WhatsApp en tu teléfono → Ajustes → Dispositivos vinculados
  4. Escanea el QR code
  5. La terminal mostrará: "✅ WhatsApp conectado"

  El servidor queda corriendo en http://localhost:3000

4.6 Ejecutar como servicio (producción)
───────────────────────────────────────
  En Linux (VPS), usa PM2 para mantener el servidor siempre activo:

    npm install -g pm2
    pm2 start server.js --name whatsapp-server
    pm2 save
    pm2 startup

  En Windows, puedes usar el Programador de Tareas o NSSM (Non-Sucking Service Manager).

4.7 Configuración en el sistema PHP
───────────────────────────────────
  En app/Config/config.php o en el archivo .env:

    WHATSAPP_API_URL = 'http://localhost:3000/enviar-pedido'
    WHATSAPP_TIMEOUT = 10
    WHATSAPP_ADMIN_PHONE = '584125181629'   ← Número del admin (código país + número)

  Si el servidor Node.js está en otra máquina, cambia localhost por la IP:
    WHATSAPP_API_URL = 'http://192.168.1.100:3000/enviar-pedido'

    - Crear tarea básica
    - Acción: Iniciar un programa
    - Programa: C:\xampp\php\php.exe
    - Argumentos: C:\xampp\htdocs\multiservicio\app\Scripts\notificar_proveedores.php
    - Desencadenador: Diario a las 8:00 AM

6.1 Checklist de verificación

  ☐ Correos SMTP probados (usar test en app/Scripts/)
  ☐ WhatsApp: servidor Node.js corriendo y QR escaneado (opcional)

6.2 Problemas comunes
─────────────────────
  Error: "404 Not Found" al navegar
    → Verifica que mod_rewrite esté habilitado en Apache
    → Verifica que los archivos .htaccess estén presentes
    → En hosting, asegúrate de que AllowOverride All esté configurado

  Error: "No se pudo conectar a la base de datos"
    → Verifica credenciales en app/Config/config.php o .env
    → Asegúrate de que la base de datos exista y el usuario tenga permisos

  Error: "Class 'Dompdf\Dompdf' not found"
    → Ejecuta: composer install
    → Verifica que vendor/autoload.php exista

  Error: "Class 'chillerlan\QRCode\QRCode' not found"
    → Ejecuta: composer require chillerlan/php-qrcode
    → O reinstala: composer install

  Error: "No se pudo enviar el correo"
    → Verifica credenciales SMTP
    → Para Gmail: usa contraseña de aplicación, no la contraseña normal
    → Verifica que el puerto SMTP no esté bloqueado por el firewall del hosting

  Error: WhatsApp no envía mensajes
    → Verifica que el servidor Node.js esté corriendo (node server.js)
    → Verifica que el QR code fue escaneado y WhatsApp está conectado
    → Verifica que WHATSAPP_API_URL apunte al puerto correcto
    → El sistema muestra un toast de advertencia si WhatsApp no está disponible

  Error: "getallheaders() not found"
    → El sistema ya incluye un polyfill en config.php para FastCGI
    → Si persiste, verifica que Apache esté usando mod_php (no CGI/FastCGI)

  Error: Imágenes no se suben
    → Verifica permisos de public_html/uploads/ (777 en Linux)
    → Verifica que la extensión fileinfo esté habilitada
